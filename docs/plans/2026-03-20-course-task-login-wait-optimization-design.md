# 课程任务登录等待优化设计

## 目标

缩短带缓存登录态时的课程任务抓取耗时，避免页面仍在加载课程内容时误判为需要重新登录。

## 根因

当前流程在 `goto(mycourse)` 之后，只立即检查一次 DOM 是否已经出现任务入口。真实站点在带缓存登录态时，URL 会保持在 `mycourse`，但课程内容往往会延迟几秒渲染进 DOM。于是代码会错过已登录页面，转而走错误的默认登录选择器分支。

## 方案

- 保留总超时兜底，不做全局粗暴缩短。
- 当本地存在 `playwright_auth_state.json` 时，`goto()` 后先进行一次短窗口等待。
- 这段短等待只等待两类信号中的任意一个：
  - 页面已渲染出课程入口（如 `data-xy-click-pt="unstudy-task"` 或 `待完成任务`）
  - 页面已跳到登录链路 URL
- 若命中课程页信号，直接继续抓任务接口，不再尝试重新登录。
- 若命中登录链路，再走现有统一认证流程。

## 测试

- 增加单测覆盖“已有登录态但课程 DOM 延迟出现时，不重新填账号密码”。
- 保留“登录态失效时自动回退登录”的现有测试，确保优化没有破坏回退路径。
