# 今日失败邮件自动重试设计

## 1. 目标

在保持现有定时发送规则不变的前提下，增加一个更直观的补偿行为：
- 每次运行程序时，先检查今天是否存在发送失败的邮件记录。
- 如果今天某个发送槽位的邮件曾失败且尚未成功，则本次运行自动重试一次。

本次范围只覆盖“今天”的失败记录，不扩展为历史多天失败补发。

## 2. 方案选择

采用方案 A：启动时优先重试今天失败记录。

选择理由：
- 行为符合用户直觉，手动重跑即可补发今天失败邮件。
- 改动集中在 `main.py`，不需要引入新的命令行参数。
- 不影响已成功发送的去重规则。

已知取舍：
- 如果 SMTP 超时但邮件实际上已投递，自动重试仍可能造成重复邮件。
- 这是 SMTP 场景下无法完全避免的现实取舍；当前方案接受该风险。

## 3. 规则定义

自动重试规则：
- 每次运行时，检查今天 `noon` 和 `evening` 两个槽位的状态记录。
- 仅当记录满足以下全部条件时才自动重试：
  - `status == "failed"`
  - `email_sent == false`
  - 记录日期等于今天
- 每个槽位每次运行最多重试一次。

保留规则：
- 已成功发送的记录仍然不重发。
- 正常 `12:00` / `18:00` 定时发送逻辑保持不变。
- 历史多天失败记录仍不在本次需求范围内。

## 4. 系统结构

调整模块：
- `main.py`：新增“今日失败记录重试”入口与辅助函数。
- `tests/test_main.py`：增加运行时自动重试今天失败记录的行为测试。

本次不修改：
- `delivery_state.py`：状态结构已足够表达失败与成功。
- `email_sender.py`：发送实现保持不变。
- `config.py`：不新增配置项。

## 5. 数据流

运行时流程调整为：
1. 读取配置与状态存储。
2. 清理过期状态。
3. 先检查今天是否存在失败的 `noon` / `evening` 记录。
4. 若存在失败记录，则按对应槽位重新生成当天邮件内容并尝试发送。
5. 若发送成功，更新状态为 `sent`。
6. 若发送失败，保留 `failed` 并更新时间。
7. 完成自动重试后，再继续现有补发与定时发送逻辑。

## 6. 发送内容来源

重试时不直接复用旧摘要文件内容，而是复用现有对应槽位的生成逻辑：
- `noon` 重试走中午发送逻辑。
- `evening` 重试走晚间发送逻辑。

这样可以避免维护一套单独的重试内容拼装分支，并保持邮件格式一致。

## 7. 错误处理

- 重试成功：覆盖当天对应槽位记录，状态改为 `sent`。
- 重试失败：继续保留 `failed`，并记录新的 `updated_at`。
- 若今天没有失败记录：不执行自动重试。
- 若处于正常发送时间点且失败记录已在启动阶段重试成功：后续正常发送逻辑会因为 `email_sent == true` 自动跳过重复发送。

## 8. 测试策略

- 测试今天中午失败记录在非发送窗口运行时会被自动重试。
- 测试重试成功后状态从 `failed` 变为 `sent`。
- 测试当天没有失败记录时不会额外触发发送。
- 测试重试成功后，同次运行不会因为后续定时逻辑再次重复发送。

## 9. 用户可见结果

完成后：
- 如果今天 12:00 或 18:00 的邮件发送失败，手动重新执行 `uv run python main.py` 会自动尝试补发今天失败的那封邮件。
- 已发送成功的邮件不会因为手动重跑而重复发送。
