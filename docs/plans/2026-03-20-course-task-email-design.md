# 课程待办邮件分支设计

## 1. 目标

在现有通知摘要邮件之外，新增一个独立的“课程待完成任务邮件”分支。

运行规则：
- 继续沿用当前定时发送时刻。
- 每次运行到发送时机时，发送两封邮件。
- 第一封为现有新闻摘要邮件。
- 第二封为课程待完成任务邮件，内容来自 `https://whut.ai-augmented.com/app/jx-web/mycourse`。

课程任务邮件要求：
- 抓取“待完成任务”列表。
- 提取截止日期，并尽量同时提取任务标题与课程名。
- 即使当天没有待完成任务，也要发送一封“今日没有待完成任务”的邮件。

## 2. 方案选择

采用方案 A：双管线双邮件。

即：
- 保持新闻邮件流程独立。
- 新增课程任务邮件流程。
- 在同一次运行里顺序执行两条发送管线。

选择理由：
- 对现有新闻流程侵入最小。
- 课程任务分支可以独立失败、独立重试、独立扩展。
- 后续如果再接别的站点，也能继续按“新管线”方式扩展。

不采用单邮件合并方案，因为用户明确要求每次发送两封邮件。

## 3. 登录与抓取方式

目标页面访问时会跳转到智慧理工大统一登录界面，登录流程为：
- 访问课程页面。
- 跳转到统一登录页。
- 提交账号与密码。
- 登录成功后回跳到个人课程页面。

因此本次设计采用“程序化登录 + 会话复用”方案：
- 使用 `requests.Session` 维持 cookie 与跳转链路。
- 先请求课程页面，获取统一登录页与必要隐藏字段。
- 解析登录表单后提交账号密码。
- 使用登录成功后的同一会话请求课程页面。

这样可以适配定时任务环境，不依赖浏览器人工登录。

## 4. 系统结构

新增模块：
- `course_client.py`
  - 负责访问课程页面、处理统一登录跳转、提交登录表单、获取最终页面 HTML。
- `course_parser.py`
  - 从课程页面中提取待完成任务列表。
  - 输出统一数据结构，例如任务标题、课程名、截止日期、原始链接或标识。

调整模块：
- `main.py`
  - 新增课程任务邮件发送流程。
  - 在原新闻邮件流程旁边执行课程任务邮件流程。
- `email_sender.py`
  - 复用发送能力，并补充课程任务邮件的主题、正文、HTML 生成函数。
- `config.py`
  - 增加课程系统账号密码及相关 URL 配置。
- `delivery_state.py`
  - 扩展状态记录，使新闻邮件与课程任务邮件各自独立追踪发送结果。

测试模块：
- `tests/test_course_parser.py`
- `tests/test_course_client.py`
- `tests/test_main.py`
- `tests/test_email_sender.py`

## 5. 数据模型

新增课程任务数据结构，建议字段至少包含：
- `title`
- `course_name`
- `deadline_text`
- `deadline_at`（若能解析成时间）
- `url` 或 `task_id`

其中：
- `deadline_text` 保留页面原始展示文本，保证即使时间解析失败，也能在邮件中展示。
- `deadline_at` 用于未来排序、过滤即将到期任务。

## 6. 发送流程

单次运行的目标流程：
1. 读取配置。
2. 执行新闻邮件相关逻辑。
3. 执行课程任务邮件逻辑。
4. 两边分别记录发送状态。

课程任务邮件流程：
1. 创建课程站点会话。
2. 请求 `mycourse` 页面。
3. 跟随跳转到统一登录页并提交账号密码。
4. 登录成功后重新获取课程页面 HTML。
5. 解析待完成任务。
6. 生成课程任务邮件正文与 HTML。
7. 发送课程任务邮件。
8. 写入课程任务邮件状态记录。

## 7. 状态管理

课程任务邮件不能与新闻邮件共用同一组状态键。

建议扩展状态记录维度，区分邮件类型：
- `news_noon`
- `news_evening`
- `course_tasks_noon`
- `course_tasks_evening`

或等价的 `kind + slot` 结构。

核心要求：
- 新闻邮件失败不影响课程任务邮件的去重与重试。
- 课程任务邮件失败不影响新闻邮件的去重与重试。

## 8. 空任务策略

若页面中没有待完成任务：
- 仍然发送课程任务邮件。
- 邮件正文明确写“今日没有待完成任务”。

这样可以区分两种情况：
- 任务系统正常抓取，但确实没有任务。
- 抓取流程失败，导致未能获取任务。

## 9. 错误处理

课程任务分支的错误处理原则：
- 登录失败：记录课程任务邮件失败，打印明确错误，不阻断新闻邮件。
- 页面结构变化导致解析失败：记录失败，并保留原始 HTML 诊断入口的扩展空间。
- 邮件发送失败：仅影响课程任务邮件状态，不覆盖新闻邮件状态。

同一次运行中：
- 新闻邮件与课程任务邮件分别 try/except。
- 一边失败，另一边仍继续执行。

## 10. 测试策略

测试重点：
- 能解析统一登录页表单并构造登录请求。
- 能从课程页面提取待完成任务与截止日期。
- 无任务时仍发送课程任务空邮件。
- 同一次运行会发送两封邮件。
- 课程任务邮件失败不影响新闻邮件发送。
- 课程任务邮件状态与新闻邮件状态独立。

为了避免测试依赖真实网站：
- 使用本地 HTML fixture 模拟登录页与课程页。
- 使用 mock session 模拟跳转与响应。

## 11. 配置项

新增环境变量建议：
- `COURSE_PAGE_URL`
- `SMART_WHUT_USERNAME`
- `SMART_WHUT_PASSWORD`

如后续有需要，可再扩展：
- `COURSE_LOGIN_TIMEOUT`
- `COURSE_TASK_EMAIL_ENABLED`

本次先保持最小配置集。

## 12. 用户可见结果

完成后，用户在每天定时发送时会收到两封邮件：
- 一封是现有的通知摘要邮件。
- 一封是课程待完成任务邮件。

课程任务邮件中会显示：
- 待完成任务名称
- 所属课程
- 截止日期

若没有任务，则会明确显示“今日没有待完成任务”。
