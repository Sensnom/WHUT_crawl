# 课程任务每次运行发送设计

## 背景

当前 `main.py` 只会在 `12:00` 和 `18:00` 的发送窗口里发送课程任务邮件。这导致手动执行 `uv run python main.py` 时，即使课程任务抓取成功，也不会立即给用户发送课程任务结果。

## 目标

- 新闻摘要邮件继续保持原有定时窗口行为。
- 课程任务邮件改为每次执行 `main.py` 都发送一次。
- 同一次运行内只发送一封课程任务邮件，不因处于 noon/evening 窗口而重复发送。

## 设计

- `run()` 在完成清理、失败重试和补发检查后，无论当前是否处于 `12:00/18:00` 窗口，都执行一次课程任务邮件发送。
- 若当前处于 `noon` 或 `evening` 窗口，课程任务邮件沿用对应 slot，便于保留原有主题和状态槽位。
- 若当前不在发送窗口，课程任务邮件使用 `manual` 作为内部 slot；邮件主题仍复用默认课程任务主题格式。
- 新闻摘要分支保持现状，只在 `noon/evening` 窗口中执行。

## 状态记录

- `course_tasks_noon` / `course_tasks_evening` 继续用于计划内运行。
- 新增 `course_tasks_manual` 槽位记录非窗口时间手动运行结果。
- 手动重复运行同一天任务时，允许覆盖当日 `course_tasks_manual` 记录，因为目标是“每次运行都发一次”，不是“每天只发一次”。

## 测试

- 新增回归测试：非 `12:00/18:00` 时间运行时，新闻邮件不发送，但课程任务邮件会发送。
- 保留现有 noon/evening 双邮件测试，确保新闻逻辑不受影响。
