# 课程任务 Playwright 登录态复用设计

## 目标

减少课程任务抓取过程中重复登录统一认证的次数：优先复用本地 Playwright 登录态，只有登录态失效时才重新走完整登录流程。

## 方案

- 在 `output` 目录下保存 Playwright storage state 文件：`playwright_auth_state.json`。
- `CourseClient.fetch_course_page_html()` 每次启动时先检查该文件是否存在。
- 如果存在，则优先带着该状态打开 `mycourse` 页面。
- 如果页面已经是课程页并能拿到“待完成任务”，直接继续后续任务抓取，不再重复登录。
- 如果仍然跳回登录页，则自动执行现有统一身份认证流程，并在成功进入课程页后刷新 storage state 文件。

## 边界

- 不新增额外配置项，状态文件路径固定放在 `output` 下。
- 不做多账号区分；当前项目只服务单一账号使用场景。
- 不把 storage state 当作长期可靠凭据，只把它视为减少重复登录的本地缓存。

## 测试

- 增加单测覆盖“已有状态时直接复用，不再填写账号密码”。
- 增加单测覆盖“已有状态但失效时，自动重新登录并刷新状态文件”。
